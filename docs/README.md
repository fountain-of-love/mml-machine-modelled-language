# Documentation

This directory contains all explanatory, architectural, benchmark, and exploratory documentation for MML and the proposed SOS direction.

The canonical MML research triad is:

> **Represent meaning. Compile knowledge. Compose concepts.**

The documentation follows that progression from definition, through current mechanisms, to evidence and downstream architecture.

## Core Reading Path

1. [Words Carry Weight: The Essence](words-carry-weight-essence.md) — introduces all three hypotheses through the minimal experiment and its richer direction.
2. [What](What.md) — defines Representation, Knowledge State Execution, and Combinatorial Uniqueness as one cumulative architecture.
3. [Why](Why.md) — why explicit representation, compiled reuse, and runtime composition may relocate work currently assigned to learned models; sustainability is treated as a consequence to test.
4. [How](How.md) — shows the current representation, compilation, activation, soft-intersection, and update mechanisms.
5. [MML in depth](MML-In-Depth.md) — expands Represent–Compile–Compose into semantic contracts, compiled operators, soft intersection, execution strategies, and future operator-family evolution.
6. [Research contract](Research-Contract.md) — states each hypothesis independently, records its present status, and separates the evidence still required.

## Deeper Areas

- [SOS architecture](sos/README.md) — downstream CML, persistence, governance, engine, and modular-pipeline proposals.
- [Combinatorial uniqueness](Combinatorial-Uniqueness.md) — develops the third hypothesis: why broad conceptual constraints may form a distinctive, inspectable intersection and how to test that claim.
- [Activate Grounded Focus vocabulary](activate-grounded-focus-vocabulary.md) — governed meanings, code projections, responsibilities, and drift boundaries for the minimal kernel and demonstration.
- [Semantic flow application architecture](Semantic-Flow-Application-Architecture.md) — the fishbone application direction, why a tiny experiment sets precedent, and how strong boundaries orient future AI-assisted growth.
- [Retrieval diagnostic](benchmark/README.md) — benchmark intention, fixtures, limitations, and reports.
- [Knowledge State Execution experiment](benchmark/results/knowledge-state-v1.md) — exact typed-chain execution, compiled reuse, governed mutation, and separate accounting boundaries.
- [MML hypothesis benchmark programme](benchmark/semantic-operator-benchmark-proposal.md) — separates tests for semantic Representation, Knowledge State Execution, and Combinatorial Uniqueness so evidence cannot leak between hypotheses.
- [OSCARC research-reporting methodology](benchmark/oscarc-methodology.md) — guides readers from observations through standards, chronology, interventions, measured results, bounded conformity judgments, and next steps.
- [Scientific and architectural explorations](explorations/README.md) — the Semantic Seed Vault, its bounded five-domain representation theorem, and the governed structure that could feed future MML operators.
- [Enigma](enigma.md) — the account-level context-engineering model used to articulate this research.

The root [README](../README.md) leads with the essence. The remaining documents progressively elaborate it; their additional mechanisms and architecture should not be read as alternative definitions of MML.
